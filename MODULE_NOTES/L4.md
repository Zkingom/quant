# L4：下单链路与 tick-to-trade

> 设计：docs/design/L4_DESIGN.md（2026-11-05 作者确认，§6 全部按推荐）。范围与进度：ROADMAP §2.4–2.6。决策：D-059–D-064。
> 开发与测量环境：云端容器（4 vCPU，Linux 6.18，GCC 13.3，Clang 18.1.3），**不是**作者的 WSL2；墙钟数字只用于验证方法，本机待复测。
> 依据的规范：Nasdaq OUCH 4.2（2025-10）与 SoupBinTCP 3.00，逐字段核对；规范未写、由本项目决定之处在代码与文档里标为"本项目约定"。
>
> **状态**：L4.1–L4.6 完成并合并（PR #6，2026-11-05）；L1 冻结语义未改动；进程内交易路径的已记录哈希一个都没变（D-059）。项目范围到 L4 为止。

模块图（新增部分）：

```
ITCH 帧 ─▶ FeedHandler ─▶ TradingStage<S, Ex> ─▶ 风控 ─▶ Ex
                                                         ├─ SimExchange（进程内，默认，代码路径不变）
                                                         ├─ LockstepExchange / FreeRunExchange（L4.5）
                                                         │     └─ OrderGateway（L4.4）─▶ OUCH 编码（L4.1）
                                                         │           └─ ClientSession（SoupBinTCP，L4.2）─▶ TCP
                                                         └─ ReplayExchange（离线重放自由运行的记录）
TCP ─▶ EpollServer（L4.3，单线程）─▶ ServerConnection（SoupBinTCP）─▶ OuchExchange
                                       ├─ 自己的 FeedHandler（交易所看到的公共订单簿）
                                       └─ SimExchange ─▶ L1 MatchingEngine（未改动）
控制队列（SPSC + eventfd）：行情输入 / 逐事件推进 / 屏障 / 收盘 / 停止
```

## L4.1 OUCH 4.2 子集编解码（`include/lob/ouch/ouch.hpp`）

- 入站 Enter Order 49 / Replace Order 47 / Cancel Order 19；出站 System Event 10 / Accepted 66 / Replaced 80 / Canceled 28 / Executed 40 / Rejected 24；
  子集外的规范类型（入站 Modify 20；出站 B 32、G 45、D 38、P 23、I 23、T 36、M 28）按精确长度 `Skipped`。两个方向分开解码。
- 只执行规范定义的校验（D-060）；规范没约束的字段原样保留，所以 `encode(decode(x)) == x` 对每个合法输入成立。
- 语义要点写在头文件与测试里：Cancel 的 Shares 是**目标剩余量**（幂等）；Replace 的 Shares 是**整条改单链的总责任量**；Replaced 的 Shares 是改单后的挂单量。

**测试**（`lob_ouch_tests` 22 项）：每种消息一个按规范偏移手写的十六进制样本，同时钉住解码结果与编码输出；每个样本的全部截断与多一字节；
每种类型字节按方向的未定义值；每个被校验字段的非法值与边界合法值；8 个种子 × 5 000 次变异 fuzz（解码成功则重编码相等，且至少 2% 的输入走到深层校验）；
金样本文件（也是 libFuzzer 种子）。libFuzzer（`scripts/fuzz_ouch.sh`，clang + ASan + UBSan）60 s 约 1 440 万次，无发现。
负对照：Accepted 的两个字段偏移互换、ISO 枚举多放一个值 → 5 个测试失败。

## L4.2 SoupBinTCP 3.00（`include/lob/soup/*.hpp`）

- 分帧：完整包零拷贝交付，跨块的包在固定缓冲区里拼接；长度 0 或超上限（数据包 256、Debug 4096，本项目约定）为协议错误。
- 客户端：`Disconnected → LoginSent → LoggedIn → LogoutSent`，终态 `Rejected` / `SessionEnded` / `Failed`（序号或会话与请求不符）；
  隐式序号跨重连保留；1 s 心跳、15 s 链路超时；收到的 Server Heartbeat 计数（重放结束的信号，L4.4）。
- 服务端：`SessionLog`（当天的序号消息，固定容量）+ `ServerConnection`（`AwaitLogin → LoggedIn → Closed`）：凭据不区分大小写、`J 'A'` / `J 'S'`、
  30 s 登录超时、按发送缓冲余量从日志**拉取**、慢消费者关闭、发完后 End of Session（D-061）。

**测试**（`lob_soup_tests` 48 项）：客户端与服务端每个转换一个具名测试（`LoginSent_LoginAccepted_GoesLoggedInAndAdoptsSession` 这样命名）；
在每个字节边界两刀切成三块与一次喂一个字节，结果与整块相同；随机字节喂两端不崩溃且"交付条数 + 1 == 期望序号"；
客户端 ↔ 服务端随机分块、随机断线重连的端到端（20 个种子）：每条消息恰好一次、按序。负对照：心跳边界 `>=` 改 `>`、重放起点加一 → 6 个测试失败。

## L4.3 模拟交易所与 epoll 服务端（`include/lob/net/ouch_exchange.hpp`、`epoll_server.hpp`）

- `OuchExchange`（sans-IO）：交易所自己的 `FeedHandler` + `SimExchange`（L1 引擎未改动）；重复令牌忽略、Cancel 目标剩余量（多余的忽略）、
  Replace 的四种结局、Rejected 消耗令牌、IOC 余量 `Canceled 'I'`；子集策略回规范原因码；整数令牌桶限流（`Rejected 'x'`，撤单不限流）；
  断线撤单 `Canceled 'Z'`（按 id 升序，编入序号）；部分撤单 = `SimExchange::reduce`（撤 + 同 id 重入，保留公共队列位置）（D-062）。
- `EpollServer`：水平触发、非阻塞、`TCP_NODELAY`；第一个包确定账户；登录成功接管同账户旧连接；控制队列（SPSC + eventfd）；
  按连接计数的屏障（L4.5）；可选的处理日志（L4.5 重放）与入站钩子（L4.6 计时）。

**测试**：`lob_net_tests` 26 项（规范行为、子集策略、限流、断线撤单、部分撤单保留队列位置、确定性）；
`lob_net_loopback_tests` 7 项（真实回环 TCP，服务端独立线程，标签 `concurrency` 进 TSan；连续 30 次无失败）。
负对照：断线撤单改为降序、非法改单错误地消耗新令牌、"多余撤单"的边界（等价变异，补充计数断言后检出）。

## L4.4 客户端订单网关（`include/lob/gateway/gateway.hpp`）

- 令牌 `[日期 4][启动序号 2][计数 8]`（base 36）：自己的令牌按计数直接找到记录，无哈希表、无分配；启动序号持久化，进程重启后令牌不重复。
- 每单状态机 `PendingNew / Live / Filled / Canceled / Rejected` + 撤单 / 改单标志；回报转换成与进程内 `SimExchange` 相同的 `sim::Report`。
- 非法转换（未知令牌、超量成交、终态后的消息、无法解码 / 子集外的消息）→ `inconsistent()` → `TradingStage` 熔断（`GatewayInconsistent`）并撤全部。
- 重连：重发待定的撤单 / 改单（幂等）；默认不重发新单（过时）；登录后第一个 Server Heartbeat = 重放结束，此时仍无回音的新单判为未到达。
- `TradingStage<S, Ex>`：默认 `Ex = SimExchange`，代码路径不变（指令数 −0.57%，摘要不变）；撤全部按 `client_id` 升序（D-059），已记录哈希无一改变。

**测试**（`lob_gateway_tests` 27 项）：每个转换一个具名测试、非法转换、重连规则三项、网关直连交易所核心（无 socket）持仓与在途量一致；
另有 `SimExchange.OpenIdsAreAscendingWhateverTheSlotOrder`。负对照：去掉超量检查、无条件丢弃在途新单 → 各有测试失败。

## L4.5 锁步与自由运行（`include/lob/net/lockstep.hpp`）

- 锁步（`LockstepExchange`）：每一步后发屏障，读到服务端给出的出站序号水位为止；只在我方有在途订单时才把行情事件发给交易所（D-063）。
- 自由运行（`FreeRunExchange`）：不等待；记录客户端每个投递点交付的条数（含断线、重放结束）；可在指定的行情事件处断线重连；结束时撤全部并排空。
- 重放：交易所日志 → 新的 `OuchExchange`；客户端日志 + 交易所的出站消息 → `ReplayExchange` + 新的网关与策略。

**测试**（`lob_lockstep_tests` 4 项，标签 `concurrency`，进 TSan）：

| 测试 | 内容 | 结果 |
|---|---|---|
| `Lockstep.NetworkOrderEntryMatchesInProcessBitForBit` | 2 个种子 × 乐观 / 保守，经 OUCH / SoupBinTCP / 回环 TCP / epoll 交易所 | 订单、成交、持仓哈希、持仓、P&L、成交量、请求数与进程内**逐位相同** |
| `Lockstep.MultiThreadedPipelineAlsoMatches` | 解码线程 → SPSC → 订单簿线程 + 交易所线程 | 同上 |
| `FreeRun.InvariantsHoldAndTheRecordedRunReplaysBitForBit` | 2 个种子 × 两种模型，不等待 | 不变量全过；两端重放逐位相同 |
| `FreeRun.DisconnectsAndThrottlingKeepTheInvariants` | 三次断线（断线撤单开启）；交易所限流 2 000/s | 不变量、对账、重放全过 |

开发中发现并修正的两个问题（都由测试暴露）：Start of Day 在登录等待期间被消费，客户端日志从第 2 条开始而重放从第 1 条开始
（日志记录起始序号）；屏障按账户累计计数在断线后永远等不到（改为按连接计数，D-063）。

## L4.6 tick-to-trade（`bench/tick_to_trade.cpp` → `lob_t2t`，BENCHMARK §15）

- t0 = 帧开始解码的 TSC（`BookStage::t_decode_ptr()`，新增一次存储）；只统计产生订单的帧；三种模式分别报告：
  进程内（T1 决策、T2 编码完成）、回环（T1、T3 `send()` 返回、T4 线到交易所）、往返（T5 回执）。每个样本扣一次读时钟开销，打印环境。
- 先发后做：本帧订单发出之后才转发行情、才读回报——被测窗口里只有订单自己的 `send()`。
- 交易所服务端新增 `ServerOptions::busy_poll`（`epoll_wait(0)` 自旋），用来验证"唤醒对端"的成本。

**结果**（云端 VM 4 vCPU，gcc-release，绑核，200 000 条合成流，3 次中位数；本机复测见下文与 BENCHMARK §15.1）：

| 分段（p50） | 交易所线程睡眠 | 交易所线程忙轮询 |
|---|---:|---:|
| 进程内 tick → 本帧第一条消息编码完成 | 0.46 µs | 0.46 µs |
| 回环 tick → 本帧第一条消息 `send()` 返回 | 9.1 µs | 3.0 µs |
| 回环 客户端 `send()` → 交易所解码 | 8.0 µs | 6.0 µs |
| 往返 tick → Accepted 解码 | 28 µs | 18 µs |

结论：回环 tick-to-trade 由内核 TCP 栈与唤醒对端线程主导，软件路径只占 5%–15%；第一版测量把交易所对上一条消息的处理、
socket 轮询与行情转发（eventfd 写）算在了窗口里，逐项移出后由忙轮询实验确认剩余差距是唤醒成本（BENCHMARK §15 记录了这个排查过程）。
`t2t.smoke`（3 000 条）在六个预设里运行，保证工具可编译可运行；它的数字不报告。

**本机复测**（作者本机 WSL2，i7-12700H，2026-11-05，同样 3 次中位数；日志 `MODULE_NOTES/evidence/local_wsl2_2026-11-05/`）：

| 分段（p50） | 交易所线程睡眠 | 交易所线程忙轮询 |
|---|---:|---:|
| 进程内 tick → 本帧第一条消息编码完成 | 0.37 µs | 0.35 µs |
| 回环 tick → 本帧第一条消息 `send()` 返回 | 1.4 µs | 1.4 µs |
| 回环 客户端 `send()` → 交易所解码 | 171 µs | 166 µs |
| 往返 tick → Accepted 解码 | 447 µs | 395 µs |

上面的"唤醒成本"结论**在本机没有重现**：忙轮询前后没有差别，所以它只是云端 VM 上的结论。本机的回环传递与往返慢一个数量级以上，
原因未解释（往返在客户端同一个核上计时，不是跨核 TSC 偏差；软件路径只有 0.37 µs），见 BENCHMARK §15.1。
