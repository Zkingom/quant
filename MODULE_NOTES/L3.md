# L3'：行情层、流水线、策略与风控

> 范围与门槛见 ROADMAP §2.3（D-046）。本文件按子阶段记录实现、证据与遗留问题；阶段完成即更新。
> 开发与测量环境：云端容器（4 vCPU，Linux 6.18，GCC 13.3，Clang 18.1.3），**不是**作者的 WSL2；墙钟数字只用于验证方法。

## 1a 无锁 SPSC 环形队列（`include/lob/concurrent/spsc_queue.hpp`）

- 容量为 2 的幂；索引为不回绕的 64 位计数器，`tail - head == capacity` 即满，不浪费槽位。
- 布局：生产者侧（`tail` + 生产者私有的 `cached_head`）、消费者侧（`head` + `cached_tail`）、只读区（`mask`、缓冲区指针）
  各占一个 64 字节缓存行（`static_assert` 固定）。只有缓存副本判定"满"或"空"时才读对方的缓存行。
- memory order（理由在代码注释中逐条写明）：
  | 操作 | order | 配对 |
  |---|---|---|
  | 生产者读自己的 `tail`、消费者读自己的 `head` | relaxed | 单写者读自己的写入 |
  | 生产者写槽位后 `tail.store` | release | 消费者 `tail.load(acquire)`：看到新 tail 即看到完整元素 |
  | 消费者读槽位后 `head.store` | release | 生产者 `head.load(acquire)`：覆盖槽位前，消费者的读已完成 |
  | 不使用 seq_cst | — | 只有两个单写者单读者的"消息传递"标志，没有第三方观察两个索引的相对顺序 |
- 元素必须 trivially copyable（`static_assert`）；构造后不再分配。

**测试**（`tests/concurrent/test_spsc_queue.cpp`，标签 `concurrency`，11 个）：容量校验、空/满、容量 1、多次回绕；
与容量受限的 `std::queue` 单线程对拍（5 种容量 × 5 个种子 × 20 000 步，逐返回值逐元素比较）；
双线程压力（容量 1/2/64/65536，Release 下最多 200 万个 32 字节元素，元素带校验字段以检出撕裂读；
与 `std::queue` 交付的序列逐元素比较）；随机突发长度的双线程测试（覆盖不同填充水平下的刷新路径）。

**TSan 负对照**（gcc-tsan，`TSAN_OPTIONS=halt_on_error=1`，手工逐一注入后恢复）：

| 变异 | 结果 |
|---|---|
| `tail.store` release → relaxed | `ThreadSanitizer: data race`，检出 |
| `head.store` release → relaxed | 检出（退出码 66） |
| 生产者刷新 `head` 的 acquire → relaxed | 检出（退出码 66） |

说明 TSan 压力测试对这三处 order 是敏感的；在 x86 上这些变异不会产生可观察的错误结果（TSO），只有 TSan 的模型能发现。
