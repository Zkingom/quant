## L5.0 范围与环境（2026-11-07）

**范围**：D-066 把范围从 L4 扩展到 L5（取代 D-065 中关于 L5 的部分）；L6 与独立进程的 `lob_ouch_server` 仍是未来计划（ROADMAP §2.6）。
D-067 记录设计 §9 的默认值：仲裁窗口 200 µs，重传超时 5 ms × 最多 3 次、指数退避，重排缓冲 65 536 条（满了按补不齐处理），
补不齐时跳过缺口交给 `FeedHandler`，组播不可用时真实 socket 测试跳过。

**WSL2 回环组播实测**（`python3 -I scripts/mcast_probe.py`，完整输出：`MODULE_NOTES/evidence/L5/mcast_probe_wsl2_2026-11-07.txt`）

| 检查 | 结果 |
|---|---|
| 两个组（239.255.0.1 / .2）在接口 127.0.0.1 上各收 200 个包（A/B 两路），`IP_MULTICAST_LOOP=1` | 3 次运行均 200/200，按序 |
| 收到组播包后向发送方地址回单播（MoldUDP64 重传请求 / 应答的路径） | 3 次均收到 |
| `lo` 的接口标志 | `<LOOPBACK,UP,LOWER_UP>`，**没有 `MULTICAST`**；不影响以 127.0.0.1 为接口加入组与发送 |
| 接收缓冲 | `rmem_default` = `rmem_max` = 212 992 字节（`SO_RCVBUF` 同） |
| 无读者时突发 100 000 个 1 008 字节的包 | 收到 93 个，丢 99 907 个；随后一个包携带的 `SO_RXQ_OVFL` 累计丢包计数 = 99 907，与实际相符 |

结论与对后续阶段的影响：
- 回环组播在本机可用，L5.4 的真实 socket 测试可以在本机运行（不需要替代方案）。环境不支持时（加入组播组失败）测试 `GTEST_SKIP` 并写明原因（D-067）。
- 内核接收缓冲只有约 200 KB，且提高 `rmem_max` 需要改系统设置（本项目不改）。发送端只要领先接收端约 200 个 1 KB 的包就会被内核丢弃，
  所以真实 socket 测试要得到确定的结果必须有流控（发送端领先量有上限）；具体机制在 L5.4 决定并写入 DECISIONS。
- `SO_RXQ_OVFL` 计数可靠，L5.4 用它统计并报告内核丢包。
- 限制：回环不经过网卡与交换机，A、B 两路在这里只是两个 socket（设计 §7）；mirrored 网络模式对回环时延的影响未测（L5.5 测量时注明）。
- GitHub Actions 的 runner（ubuntu-24.04，非 WSL）是否支持回环组播在 L5.4 的首次 CI 运行中确认并记录。

**其他**：本地 `main` 与 `origin/main` 分叉（本地有 5 个从未推送的旧 L3 网关提交，已被 D-046 废弃），本地 main 保存为分支 `backup/local-main-old-l3`
后对齐 origin；仓库历史不受影响。
